# 児童の端末のAI:試したことと、決めたこと(11/5)

## 決めたこと

| 役目 | だれがやるか | 理由 |
|---|---|---|
| 質問の答えになる文を、教材から探す | **プログラム**(`Intl.Segmenter` で単語に区切り、重なりを数える) | AIなしで 9/11。教材の文しか出さないので、まちがった内容が出ない。AIが使えない iPad 6/7 でも動く |
| 探した文を、質問への答えらしい1文に直す | 端末のAI(Gemma 3 1B など) | AIの文はプログラムで調べ、あやしいときは教材の文だけを見せる |
| 説明を学年に合わせて言いかえる | 端末のAI | 1文ずつ言いかえさせ、1文ずつ調べる。だめな文は、もとの文のまま |
| 確認問題の答えをたずねる質問 | **プログラム**(AIを使わない) | 答えを言わせないため |

AIの文を使わない条件(`checkFaithful`):

- もとの文にない漢字・カタカナの言葉が出た(「バランス」「スピード」「観察」など)
- 打ち消し(〜ない、〜ません)が、もとの文と合わない
- もとの文の漢字の言葉が、6割より多く消えた(言いかえのときは見ない)

## モデル

| 端末 | モデル(WebLLM 0.2.86) | 大きさ |
|---|---|---|
| WebGPU + 16ビット計算(shader-f16)あり | Gemma 3 1B `gemma3-1b-it-q4f16_1-MLC` | 約574MB |
| WebGPU あり、16ビット計算なし | Qwen2.5 0.5B `Qwen2.5-0.5B-Instruct-q4f32_1-MLC` | 約276MB |
| テスト用に選べる | Gemma 4 E2B `gemma-4-E2B-it-q4f32_1-MLC` | 約2.7GB |
| WebGPU なし(iPad 6/7 など) | AIなし。「さがす」と「先生に聞く」だけ | - |

LiteRT-LM の Web 版は、Gemma 3 1B が「Hugging Face で同意が必要なモデル」の例として出てくるだけで、対応モデルの一覧は Gemma 4 だけだったので、今は WebLLM を使う。

## 試した結果(手元の Ollama `gemma3:1b`、同じ指示文)

教材:「ふりこのひもが長いと、1往復する時間が長くなります。ひもが短いと、1往復する時間は短くなります。おもりの重さやふれはばを変えても、1往復する時間はほとんど変わりません。」

1. **自由に答えさせる**:速い(0.3〜4秒)が、内容がくずれる。
   - 「おもりを重くしたら?」→「書いていない」と答えたうえ、「重くすると長くなるかな?」とまちがったヒント
   - 「電磁石を強くするには?」→「ひもを長くしたり、おもりを重くしたりすると、電磁石が強くなるかも」
2. **答えの文の番号を選ばせる**:4/9。何を聞いても、ほぼ「2番」を選ぶ。
3. **1文ずつ「答えになるか」を、はい/いいえで判定させる**:2/10。ほとんど「はい」と答える。
4. **単語の重なり(AIなし)**:8/10 → 用語の扱いを直して 9/11。
5. **探した文を、答えらしく直させる**:0/5 が合格(「はい、承知いたしました」「お子さんが自分で確かめることで…」)。調べるしくみが、全部止めた。
6. **説明の言いかえ**:0/6 が合格(「おばけが踊る時間が長くなるよ」など)。調べるしくみが、全部止めた。

**わかったこと**:1B のモデルは、日本語で子ども向けに書き直す力が足りない。児童に見せる文の正しさは、プログラムで守る。Gemma 4 E2B が動く端末では、5・6 がどれだけ良くなるかを、実際の端末で確かめる(児童用アプリの「テスト表示」で、AIの出力と、使わなかった理由が見られる)。

試し方:`node server/try-student-ai.js`(Ollama に `gemma3:1b` が必要)

## Gemma 4 E2B に切りかえた(11/5 夜)

児童の質問には「それ」「これ」が多いと考え、具体化と答えづくりができる Gemma 4 E2B を基本にした。クラスに入ると自動で準備する(WebGPU がない端末はしない)。

流れ:あいまいな質問(プログラムで判定:教材の用語を消してから「それ」「これ」などを単語で探す)→ AIが具体的な質問の候補を1〜3つ出し「こういうこと?」でえらぶ → AIがシミュレーションで計った結果をもとに答え、変えてみる条件と確かめ方を決める → 結果と食いちがう答えは出さず、計った結果の文を見せる → わからなければ、具体化した質問ともとの言い方を先生に送る。

このPC(Intel 内蔵GPU、Edge)で試した結果:

| | 結果 |
|---|---|
| ダウンロード | 2.7GB に約104秒。保存したあとは約16秒で使える |
| 速さ | 最初の1回は約60秒(GPUの準備)、そのあと1回 16〜39秒 |
| 「それって重いとどうなるの?」 | 「おもりの重さを変えると、1往復する時間はどうなるの?」など2つ → 答え「変わらないよ。10gから200gにしても2.02秒のまま」(正しい) |
| 「これ長くしたら?」 | 教材の条件をわたすと「ひもの長さを長くすると…」(わたす前は「おもりを長く」とずれた) |
| 答えの向きのまちがい | 「ひもを長くすると、1往復する時間は速くなります」→ 向きの検査で止め、計った結果の文を見せた |

検査(`checkAgainstFacts`、先生の側と共通):変わらない条件で「変わる」と書く/変わる条件で「変わらない」と書く/条件を大きくしたときの向きが逆、を見つける。

## ことばの辞書(AIなしの読みとり)を自分で育てる(2026-11-08)
- 児童の言い方は、まず `public/js/sim2/systems/student-words.json` の辞書で読む(AIを使わず 1 ミリ秒前後)。読めないときだけ Gemma を使う。
- コードを書かずに編集できる:
  - `kana`:ひらがな → 漢字(例 `["ちいさめ", "小さめ"]`)
  - `up` / `down`:大きくする・小さくする向きのことば
  - `implied`:条件の名前がなくても決まる向きのことば(「重く」→ おもりの重さ)
  - `systems.<系>.aliases`:条件の別名(例 heat の `d` に「温度計」)
  - `systems.<系>.phrases`:言い回しまるごと(例「音を高く」→ f を上げる)
  - `explain`:説明の ID と、それを選ぶことば
- 編集のあと:`python tools/build-json-modules.py` → `node --test tests/sim2-student-words.test.js` → `node tools/build-offline.mjs`
- 評価:`node eval/run-student.mjs local`(いつものセット)、`STUDENT_SET=student-holdout.jsonl` / `STUDENT_SET=student-blind.jsonl` で別のセット。
  - 新しい言い方を辞書に足すときは、先に評価セットに書いてから足す(辞書に合わせた点数だけを見ないため)。
- 結果(2026-11-08):いつもの 50件 88% → 100%、確認用 44件 34% → 100%(辞書を作るときに見たセット)、初見 22件 55% → 95%(初見で測ってから一般の規則を直した)。
